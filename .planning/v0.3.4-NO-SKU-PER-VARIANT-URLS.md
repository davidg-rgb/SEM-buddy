# v0.3.4 — No SKU in customer copy + per-variant `text=N` URLs

> **Shipped:** 2026-05-21
> **Status:** Done. 80 focused tests pass (variant + catalog + ad-copy + URL templating), 4,580 RSAs generated across 963 ad groups, all four v0.3.4 contract audits return zero failures, spell-check returns zero flagged tokens.
> **Driver:** Operator brief mid-session (no SKU in customer copy) + four contract audits + a reviewer-agent pass on the stratified QA sample. Findings live in `.planning/NEXT-SESSION-HANDOFF.md` (the prior brief).

---

## Problem

The v0.3.3 pattern pack still leaked the IATA code into customer-facing copy on every long-name destination (PKC, FEN, BWN, etc.) via the `long_name_fallback_patterns` block, which substituted `{sku}` into headlines like `Avoid PKC fare hikes` and `PKC fares from $224`. The operator's hard rule mid-session: **customer never sees the airport code** — that's an analytics token, not ad copy.

Three other contracts were not met:

- **Variant attribution at the URL layer.** Operator's wording: *"the different ad versions are labeled as text=1, text=2, text=3 etc."* The v0.3.3 builder rotated `text=N` per ad group, so two variants in the same ad group shared the same `text=` value — making it impossible to attribute SERP performance to a specific variant.
- **Mandatory canonical discount headline.** Every discounted ad group needed a `Save up to {pct}% to {name}` headline — present in *some* variants but not guaranteed across the 870+ discounted destinations.
- **`from_price` guarantee.** Every ad group with a known `from_price` had to surface the literal `$<price>` token in at least one headline or description. The pattern pack supported it, but a sizeable minority of ad groups silently shipped without it (rejected by `_fit_to_limit` truncation guards).

A fresh reviewer-agent pass on a stratified 32-ad-group QA sample also caught six pattern-level slop issues — orphan first-name truncations on long-name destinations, a transcription typo in the source XLSX (`Petropavlovsk-Kamchats` missing the `-ky` suffix), `Cheap Flights to {name}` leaking via the title-cased keyword fallback path, and three Trustpilot/Fares-update semantic-similarity collisions that would dampen Google's RSA optimizer.

---

## Solution

### A. No SKU/IATA in customer copy

- **`_resolve_customer_display_name(product, max_chars)`** is now the single source of truth for the `{name}` substitution. The hierarchy: `product.short_name` → paren-stripped name → comma-segment → paren-strip + comma-segment → particle-strip (`San Carlos De Bariloche` → `San Carlos Bariloche`) → head-token surfacing (NEW, see fix 3.1) → full name (caller's `_fit_to_limit` may still reject). **Never** falls back to the SKU.
- **`IATA_HOUSEHOLD_CODES`** is now an empty frozenset shim — kept only to avoid breaking external imports. `_should_use_iata_in_customer_copy()` hard-codes to `False`.
- **`_fill_pattern` substitution map**: `fills["sku"] = ""`, so any legacy pattern that still references `{sku}` renders to empty and is rejected by the downstream guards.
- **Pattern pack v4 (now v4.1)**: every `{sku}` substitution in `long_name_fallback_patterns` was replaced with `{name}`. The customer always sees the destination by name.

### B. Per-variant `text=N` URLs

- **`_resolve_path1_path2` and the campaign builder** previously rotated `text=N` per ad group through an `NCycler` in `_structure_by_sku`. That cycler is gone.
- **`generate_rsa_variants` now accepts `final_url_template` + `text_n_range`** and renders the URL inside the loop: variant index 0 → `text=N_low`, variant 1 → `N_low+1`, …, wrapping at `text_n_range[1]` if there are more variants than slots (the operator accepts wrap when `text_n_range` is intentionally narrower than the variant count).
- **Keyword `final_url`** and the ad-group fallback URL (used for Path1/Path2 derivation) use `text=N_low` (= 1), aligning with the first variant.
- **Audit (mission 3):** zero ad groups have duplicate `text=N` across the full 963-destination catalog.

### C. Mandatory `Save up to {pct}% to {name}` headline

- **`generate_headlines_for_variant`** force-injects a `Save up to {pct}% to {name}` headline into every `discount_led` variant whose product has `discount_pct >= 0.15`, with a fit-aware fallback chain (canonical → `to → on` → drop `up to` → drop preposition → `{name}: save {pct}%` → `{name} -{pct}%` → `Save up to {pct}% today` name-stripped fallback).
- **Resolver budget computation**: `_fill_pattern` now computes the ACTUAL pattern overhead (rendering every other token first, measuring the residual) before passing the budget to `_resolve_customer_display_name`. Long-overhead patterns like `Save up to {pct}% to {name}` (~18 chars of fixed overhead) reserve 12 chars for `{name}`; short-overhead patterns like `{name}` reserve all 30. Fixes the chronic under-allocation of name budget that produced the v3 orphan-first-name pathology.
- **Orphan-prevention guard in the injection block**: if the resolved name is multi-word, every word of the name must survive `_fit_to_limit`'s truncation. Otherwise we walk the ladder until a fully name-preserving shape fits.
- **Audit (mission 2):** zero discounted destinations missing the canonical headline across 963 ad groups.

### D. `from_price` guarantee

- **`generate_rsa_variants`** has a post-pass enforcer: after generating all variants, if the product has a known positive `from_price` but no variant surfaces the literal price token, force-inject the operator's example shape (`Get a great deal on flights to {name} with prices from $X`) as a description plus a headline into the `price_led` variant.
- **Pattern pack v4 marks** `"mandatory_when_priced": true` on the canonical price-bearing description so the variant generator prioritizes it.
- **Audit (mission 4b):** zero priced destinations missing the from_price token across 963 ad groups.

### E. Six review-driven fixes (this session)

## Seasonality bidding (added in same session — closes the brief's "temporary discount-pct steering" ask)

The original brief asks for *"temporarily steer bidding based on the
discount percentages, but also have overall target guidance and control."*
The v0.3.3 ladder gave the always-on Layer 1; v0.3.4 adds **Layer 2 — time-
windowed overlays** via the `during:` clause and a today-aware evaluator.

**Engine changes** (`src/catalog/bid_rules.py`):
- `apply_rules(..., today=date|None)` — when `today=None` defaults to
  `date.today()`. Tests pass an explicit date.
- During-rules with the same `if:` as a base rule are placed FIRST. When
  `today ∈ [start, end]` the overlay wins first-match (immediate decision
  becomes the overlay's modifier). When outside, the overlay is skipped for
  the immediate decision; the next matching base rule fires.
- Schedules emit ALWAYS (in-window or out) for documentation. Cascading
  overlays in the same window are de-duplicated per `(start, end)` so a
  55%-discount product matching three cascading overlays (`>=0.50` /
  `>=0.40` / `>=0.30`) emits ONE schedule (the first matching one), not three.

**Wired through the builder** (`src/generators/campaign_builder.py`):
- `build_campaigns_from_catalog(..., today=date|None)` propagates the date
  down to `apply_rules`. Production callers leave it unset; tests pin it.

**Real overlays in `clients/etraveli/case.yaml`**: SUMMER_SALE overlay
(2026-05-20 → 2026-08-31, matching the promotion-extension's window) for
the 30%+ / 40%+ / 50%+ discount tiers — modifiers 2.50× / 2.75× / 3.00×
overriding the base 1.80× / 2.00× / 2.25×.

**New CLI command — `sem case apply-bids <slug>`**: re-applies today's
plan to an EXISTING live campaign by `AdGroupService.mutate` with a
`cpc_bid_micros`-only FieldMask. Use as a daily cron post-push so window
flips propagate without re-creating entities. Looks up live ad groups by
`name` (pass `--name-suffix` if the original push used `--auto-suffix`).
Returns a `BidApplyReport` with intended / applied / skipped counts.

**Tests added** (5 new bid_rules + 1 builder integration + 3 pusher integration):
- `test_during_clause_fires_immediately_when_today_in_window`
- `test_during_clause_falls_through_to_base_when_outside_window`
- `test_during_overlay_does_not_block_other_base_rule_for_lower_bands`
- `test_multiple_overlays_emit_all_schedules` (summer + winter)
- `test_cascading_overlays_in_same_window_emit_only_first_match`
- `test_seasonality_overlay_fires_in_window_falls_back_out_of_window` (end-to-end)
- `test_apply_bids_dry_run_computes_intended_updates_without_api_calls`
- `test_apply_bids_live_mutates_matched_ad_groups_via_update_mask`
- `test_apply_bids_with_name_suffix_finds_suffixed_live_ad_groups`

**Operator mental model**: the same `case.yaml` produces different bid
plans depending on `date.today()`. On 2026-05-21 (in window) high-discount
bands fire the overlay; on 2026-09-01 the same product gets the base
ladder. `sem case apply-bids` is the bridge from "the YAML knows what
bidding should look like today" to "the live campaign reflects that
now" — without re-creating the campaign each window flip.
