# v0.3.2 — Multi-Variant RSAs + Discount-Driven Bidding

> **Shipped:** 2026-05-20
> **Status:** Done. All tests green, full etraveli catalog (964 destinations) generates 4,799 RSAs end-to-end in ~9s.
> **Downstream:** Live push (`sem case push etraveli`) inherits the new variants automatically — the pusher iterates `AdGroup.ads` and emits one `AdGroupAd` per variant.

---

## Problem

The v0.3 catalog engine generated **one RSA per ad group**. For a 964-destination Flightnetwork catalog that's 964 ads — fine for proof-of-concept but suboptimal because Google's RSA optimizer needs variety to actually learn. The brief from this session added three constraints:

1. **3–5 ad variations per destination.** Single-RSA per ad group caps Google's auction at one angle.
2. **Discount must appear in at least one variant per discounted destination.** The catalog has `discount_pct ∈ [0.01, 0.60]` for 943 of 964 destinations — surfacing this on the SERP is the single highest-leverage move for CTR.
3. **Bid optimization must be driven by discount rate.** The previous case.yaml had two threshold rules (≥15%, ≥30%) which left the top and bottom of the discount distribution flat-bid.

---

## Solution

### 1. Multi-variant RSA generator

`src/generators/ad_copy_generator.py::generate_rsa_variants(product)` returns 3–5 distinct `ResponsiveSearchAd` objects per product, each anchoring a different psychological lever:

| Variant | Lever stack | Emitted when |
|---|---|---|
| `price_led` | specificity + friction removal | Always |
| `discount_led` | loss aversion + scarcity + specificity | `discount_pct > 0` |
| `social_proof` | authority + risk reversal | Always |
| `urgency` | scarcity + friction removal | Always |
| `loss_aversion` | pain + friction removal | Always |

Each variant fills the full 15 headlines + 4 descriptions for "Excellent" Ad Strength. All variants share the same H1/H2 pin pair (brand + destination) and differ on H3 — the pinned CTA matches the variant's lever ("Claim 38% off now" for `discount_led`, "Compare 800+ airlines" for `social_proof`, etc.).

### 2. Variant-aware patterns + LLM prompts

`data/en/ad_copy_patterns.json` was rebuilt around the **sem-ad-copy skill's expert-tier playbook** for OTA travel:

- A `variants` block with one pattern pool per role (headlines, descriptions, and pinned CTA list)
- A `universal` block any variant can draw from to top up to 15 headlines
- All banned-phrase list from the skill's "Banned English ad-copy phrases" table avoided (no "best-in-class", "trusted partner", "transform your X", etc.)
- First-three-words doctrine: each catalog pattern leads with the number, destination, or verb

`src/generators/llm_ad_copy.py::generate_llm_ad_copy(..., variant_role=...)` accepts a variant role and rewrites the LLM prompt to lead with that lever's instruction. The variant block also enumerates the banned phrases inline so the LLM doesn't fall back to template Tier-2 output.

### 3. Discount-driven bid ladder

`clients/etraveli/case.yaml` `bid_rules:` was expanded from 2 thresholds to a full 10-band ladder. First-match-wins, so the rules are ordered largest threshold first:

```
50%+  →  2.25×   (170 destinations)
40-49% → 2.00×   (173)
30-39% → 1.80×   (143)
25-29% → 1.60×    (86)
20-24% → 1.45×    (68)
15-19% → 1.30×    (88)
10-14% → 1.15×    (86)
5-9%   → 1.05×    (77)
sub-$100 fares → 1.10×  (4 additional destinations)
else   → 1.00×    (69)
```

All 964 etraveli destinations are accounted for (verified by `tests/test_rsa_variants.py::test_bid_ladder_for_each_discount_band` across every band).

### 4. Smart bid strategy via `campaign_goals`

`case.yaml` gained a `campaign_goals:` block. Setting `goal_type: revenue` + `target_roas: 4.0` plumbs through `ClientProfile.campaign_goals` and lands in `_select_bid_strategy()` → `TARGET_ROAS` (campaign created PAUSED so the operator sets the actual target value in the UI before going ENABLED).

## Contracts (encoded as tests)

`tests/test_rsa_variants.py` — 32 tests covering:
- Variant count: 5 if discount, 4 if no discount, 4 if missing attribute
- Discount-mention contract: `discount_led` variant must contain literal `38%` (or whatever the actual %) in ≥1 headline AND ≥1 description
- Anti-leak contract: non-discount variants' H3 must NOT lead with the discount %
- Fingerprint uniqueness: no two variants share identical headline lists or pinned H3
- Ad Strength: every variant fills 15 headlines + 4 descriptions when data supports it
- CSV exporter writes the multi-variant rows (4,799 across 964 ad groups in production)
- Bid ladder: parametrized test across all 10 discount bands

`tests/test_catalog_scale.py::test_full_catalog_emits_three_to_five_variants_per_ag` — 1,000-destination scale test (gated by `SEM_RUN_SCALE_TESTS=1`) verifying the multi-variant contract holds at scale.

`tests/test_campaign_pusher.py::test_pusher_walks_full_plan` — updated assertion so the live API push tolerates 3–5 RSAs per ad group (`30 ≤ report.ads ≤ 50` for 10 ad groups).
