Each stage command's main function is registered via @app.callback(invoke_without_command=True),
meaning the function is the registered_callback of the Typer instance. To invoke programmatically
from the pipeline, we need to either:
(a) Extract the actual function and call it directly, or
(b) Use typer.testing.CliRunner (heavy), or
(c) Define stage functions as standalone and register them as callbacks

The cleanest approach for pipeline invocation: each stage module should also export a
run_stage(client_name: str, client_dir: Path, dry_run: bool, console: Console) function
that the pipeline can call directly. The Typer callback wraps this with argument parsing.

Since Plans 01+02 may not have this pattern, the pipeline_commands.py should use a mapping
of stage name to the Typer app's registered callback. Typer stores the callback as
`app.registered_callback.callback` for apps using `@app.callback()`. 

SIMPLER APPROACH: Import each stage module and call its main function by name convention.
Each stage module defines its stage function (intake, research, etc.) decorated with
@app.callback(). We can call these directly: `intake_commands.intake(client=name, dry_run=dry_run)`.
But Typer callbacks expect Typer-parsed arguments.

SIMPLEST APPROACH: Have pipeline_commands import the stage modules and invoke the Typer app
instances using typer.testing.CliRunner(app). But this is heavy.

RECOMMENDED APPROACH: Each stage command module should export a `run(name: str, client_dir: Path, dry_run: bool, console: Console)` function that does the actual work. The @app.callback wraps it with CLI argument parsing. Pipeline calls run() directly.

Since the stage commands are being built in parallel plans, the pipeline_commands should handle
the case where stage functions may have slightly different interfaces. Use a dispatch dict.

PRAGMATIC APPROACH: Import the stage_helpers + call the underlying generators directly in the
pipeline orchestrator, replicating the stage logic. This is NOT ideal (DRY violation).

BEST APPROACH: Define a `_run_stage` function in stage_helpers.py that the pipeline calls,
OR define the stage logic as functions in the stage modules and have both the Typer callback
and the pipeline call them.

For THIS plan, use: each stage module's Typer callback function IS the callable. Get it via
module introspection. The pipeline orchestrator imports each module, gets its app, and invokes
the registered callback programmatically.

Actually, the simplest correct approach: The pipeline_commands.py constructs CLI args and
uses `typer.main.get_command(stage_app)` to get the Click command, then invokes it with
`standalone_mode=False`. This is how Typer apps are tested internally.

Even simpler: use CliRunner from typer.testing. It's lightweight and correct.
```python
from typer.testing import CliRunner
runner = CliRunner()
result = runner.invoke(intake_app, args)
```

**`run` command** (per PIPE-02, PIPE-05, DRY-03):
```python
@pipeline_app.command("run")
def run(
    client: Optional[str] = typer.Argument(None, help="Client slug (defaults to active client)"),
    dry_run: bool = typer.Option(False, "--dry-run", help="Run without API calls, use synthetic data"),
    from_stage: Optional[str] = typer.Option(None, "--from", help="Start from this stage"),
    to_stage: Optional[str] = typer.Option(None, "--to", help="Stop after this stage"),
) -> None:
```

Implementation:
1. resolve_client(client) to get (name, client_dir)
2. Validate from_stage/to_stage are in PIPELINE_STAGES if provided (raise typer.BadParameter if not)
3. Determine stage range:
   - start_idx = PIPELINE_STAGES.index(from_stage) if from_stage else 0
   - end_idx = PIPELINE_STAGES.index(to_stage) if to_stage else len(PIPELINE_STAGES) - 1
   - stages_to_run = PIPELINE_STAGES[start_idx:end_idx + 1]
4. Print header: `[bold]Running pipeline for '{name}'[/bold]` + stage list
5. Import stage apps lazily inside the function to avoid circular imports:
   ```python
   from src.cli.intake_commands import intake_app
   from src.cli.research_commands import research_app
   from src.cli.competitors_commands import competitors_app
   from src.cli.keywords_commands import keywords_app
   from src.cli.campaign_commands import campaign_app
   from src.cli.validate_commands import validate_app
   from src.cli.export_commands import export_app
   from src.cli.report_commands import report_app
   ```
6. Map stage names to Typer apps:
   ```python
   stage_apps = {
       "intake": intake_app, "research": research_app,
       "competitors": competitors_app, "keywords": keywords_app,
       "campaign": campaign_app, "validate": validate_app,
       "export": export_app, "report": report_app,
   }
   ```
7. Use `typer.testing.CliRunner` to invoke each stage:
   ```python
   from typer.testing import CliRunner
   runner = CliRunner()
   ```
8. For each stage in stages_to_run:
   - Print `[bold cyan]Stage {i}/{total}: {stage}[/bold cyan]`
   - Build args list: `[name]` + `["--dry-run"]` if dry_run
   - For validate stage: no --dry-run flag (validate doesn't accept it), just `[name]`
   - `result = runner.invoke(stage_apps[stage], args)`
   - Print result.output
   - If result.exit_code != 0: print `[red]Pipeline stopped at '{stage}'[/red]`, raise typer.Exit(1)
   - Else: print `[green]  {stage} complete[/green]`
9. Print final summary: `[bold green]Pipeline complete for '{name}'[/bold green]`
   - Print `[dim]Output at: clients/{name}/exports/ and clients/{name}/reports/[/dim]`
